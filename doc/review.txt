==============================================================================
INTRODUCTION					*review* *review-nvim*

review.nvim reviews diffs between branches (git refs) inside Neovim the way
GitHub's Files changed page does, accumulates comments and exports them as a
prompt for AI agents. Persisted comments are recovered with a single `:Review`
after restarting Neovim.

==============================================================================
USAGE						*review-usage*

Everything runs through one command and its subcommands:

	:Review
	  Restore a session to continue. Only open sessions are eligible; with
	  several, a selection UI is shown. closed sessions are resumed from
	  |review-list|

	:Review start {base} [{head}]
	  Start a branch review. The review target is the working tree of the
	  current checkout (including uncommitted changes). {base} / {head} are
	  <Tab>-completed on the cmdline in branches -> tags order (fetched
	  synchronously with a short cache). With head omitted, the current
	  branch name (rev-parse --abbrev-ref HEAD; "HEAD" when detached) is
	  adopted and saved automatically — no input UI. When head is stated
	  explicitly and points at a commit other than the current HEAD, and
	  head is a local branch with a clean working tree, a [y/N] prompts
	  whether to git switch (accept = switch and review; refuse / dirty /
	  non-local branch / switch failure = fall back to a read-only review
	  of the git show content with an INFO). Branch reviews never create a
	  worktree. `:w` in the head window automatically refetches the diff
	  and reflects it in the review ("auto-apply on save" in
	  |review-sessions|). When a saved session exists for the same refs
	  pair, a carry-over [y/N] prompt appears (y carries comments /
	  completion marks over, n does nothing)

	:Review pr {number|url}
	  Start a PR review (gh integration). {number} is <Tab>-completed with
	  open PR numbers (gh runs synchronously). The head is expanded into a
	  git worktree and the head side of the review windows (tcd done)
	  becomes the real files under the worktree (worktree creation is pr
	  mode only; cleanup: |review-sessions|)

	:Review list			saved-session list |review-list|

	:Review comments
	  Open the current session's comments (after the filter is applied) as
	  a cross-file list, full-width at the bottom of the review tab (same
	  as <leader>c). If already open, that window is focused. WARN when no
	  session is active. Keys: |review-keymaps-commentlist|

	:Review close		save and close the current session |review-sessions|

	:Review delete {id}
	  Delete a saved session. <id> is <Tab>-completed with saved ids

	:Review prompt [file]			copy the prompt to the clipboard

	:Review clear
	  Delete all comments of the current session ([y/N] confirm; outdated
	  included; same as the D key from |review-keymaps-diff|; the cleanup
	  pass after copying a prompt)

Confirmation prompts ([y/N] etc.) are answered with y or n then <Enter>. The
cmdline is cleared after the answer, so the next keystroke cannot leak into
an input.

==============================================================================
API						*review-api*

Public Lua API (~require("review")~). The command equivalents are under
|review-usage|. Return values are result types `{ok, data, error, code}` and
describe only failures determinable synchronously (bad arguments, missing
active session `E_NOT_ACTIVE`, invalid config). The success or failure of
executions involving git/gh is reported asynchronously via UI open/close or
vim.notify.

	setup(opts)
	  config merge and initialization (optional; works with the defaults).
	  Options: |review-setup|

	start({ base=[, head=] })
	  Start a branch review. With head omitted, the current branch name is
	  adopted and saved automatically (no input UI). Behavior matches
	  |review-usage|

	start_pr({ number= })		start a PR review (gh, |review-usage|)
	resume({ id= })			restore a saved session by id

	close()
	  save the current session + close the windows + worktree cleanup

	delete({ id= })
	  delete a saved session (includes worktree cleanup; may be active)

	prompt_all(opts)
	  format the prompt of all comments and copy it to the clipboard/"0.
	  opts.copy = false returns text without copying (test hook)

	prompt_for_file(path, opts)	same, restricted to that file

==============================================================================
SETUP						*review-setup*

>
	require("review").setup({
		git_bin = "git",           -- git executable
		gh_bin = "gh",             -- gh executable (PR support)
		diff_context = nil,        -- diff context lines (nil = git default 3)
		auto_notify_resume = true, -- notify open sessions on startup
		panel_width = 35,          -- file panel (left window) width
		comment_list_height = 10,  -- comments-list window (full-width bottom) height
		keymaps = {},              -- buffer-local keymap overrides
		highlight = {},            -- per-group highlight overrides
		winbar = true,           -- winbar info in review windows (no line reserved outside review tabs)
		number = false,            -- line numbers in review windows (off by default; global untouched)
	})
<

setup is optional. Even without calling it the default keys are installed and
the startup resume-notify and worktree sweepscan run (registered from plugin
load). Options passed later are read at run time by the notifications in
|review-sessions|.

KEYMAPS						*review-keymaps*

All keymaps are buffer-local. Which keys are live depends on where you press
(where the buffer comes from), so look up the section below.

Defaults and the override format:

	keymaps = {
		diff = {                      -- review windows (head / base)
			add_comment    = 'c',     -- |review-comment-input|
			edit_comment   = 'e',
			delete_comment = 'd',
			delete_all     = 'D',     -- delete all comments at once
			cancel_arming  = '<Esc>', -- cancel the d / D arming
			yank_prompt    = 'y',
			close          = 'q',
			help           = '<F1>',
			next_file      = '<Tab>',
			prev_file      = '<S-Tab>',
			first_file     = '[F',
			last_file      = ']F',
			refresh        = 'R',
			focus_panel    = '<leader>e',
			toggle_panel   = '<leader>b',
			view_comments  = 'i',
			comments_list  = '<leader>c', -- cross-file comments list
		},
		sidebar = {                   -- file panel (changed files)
			open_diff      = '<CR>',
			open_file      = 'o',     -- same as <CR> (open the entry)
			open_entry     = 'l',     -- ditto
			next_file      = '<Tab>',
			prev_file      = '<S-Tab>',
			first_file     = '[F',
			last_file      = ']F',
			refresh        = 'R',
			toggle_style   = 'i',    -- list / tree view toggle
			toggle_viewed  = 'x',

			help           = '<F1>', -- g? is a fixed alias for the same call
			close          = 'q',

Review windows (head / base)			*review-keymaps-diff*

	Reviews open in a dedicated tabpage with 3 windows (file panel │ base │
	head). The head window is the real file (`:edit`, editable); the base
	window is a `git show` scratch. The two windows use Neovim's standard
	window diff, so `[c` / `]c` hunk movement and folds work as-is. The
	keys below are installed buffer-local in the head/base windows and
	fire only when the window role gate passes at press time. In windows
	that fail the gate (the same real file opened in your own window) 1
	keystroke falls back to built-in behavior (review actions never
	mis-fire).

	c
	  add a comment (head window only). visual-line for a range. base
	  window and deleted/binary notice windows show «comments are not
	  available in this window»

	e
	  edit the comment on the cursor line (input window:
	  |review-comment-input|). with several comments on the line a numbered
	  prompt appears (the default vim.ui.select = `Type number and <Enter>`)

	d
	  delete the comment on the cursor line. mis-fire guard double-press:
	  press once and it only arms + WARNs; press d again within 2s on the
	  same line to confirm (so vim-style dd cannot silently delete several).
	  The arming is cancelled by moving to another line, confirming an
	  edit with e, waiting 2s or pressing <Esc>

	D
	  delete all comments at once (same as :Review clear). mis-fire guard
	  double-press: press once and it only arms + WARNs; press again within
	  2s to confirm. A comment count change during the arming or <Esc>
	  cancels it (everything disappears, outdated included; meant for
	  cleaning leftovers after copying a prompt — never automatic)

	<Esc>
	  cancel the d / D arming (INFO). When nothing is armed the key is not
	  consumed and returns to built-in <Esc>

	y		yank the prompt of the comment on the cursor line
	q		close the session (no confirmation with 0 comments)

	<F1> / g?
	  keymap help float (rendered as markdown). g? is a fixed alias calling
	  the same function as <F1>; it is not configurable (<F1> is eaten by
	  some terminals)

	<Tab>
	  open the next file (swaps head/base; file panel display order = tree
	  top-down, reflecting folds and filter. no-op at the edges. same open
	  path as <CR> in the list — marks are untouched)

	<S-Tab>		open the previous file (same rule)
	[F		open the first file (no-op when already first)
	]F		open the last file (no-op when already last)

	R
	  refetch the diff (git diff re-run -> reparse -> anchor verification ->
	  ±counts, threads, panel update -> :diffupdate). Also the recovery
	  path when window roles got broken

	<leader>e
	  go to the file panel (changed files). If its window is closed it is
	  rebuilt on the left first

	<leader>b	toggle the file panel (closing keeps the tab and review windows)

	<leader>c
	  open the comments list (cross-file) full-width at the bottom of the
	  review tab (same as :Review comments; focuses the window if already
	  open)

	i
	  view the full comment text on the cursor line in a read-only
	  (markdown) window (edit with e). q / <Esc> closes

 file panel (changed files)			*review-keymaps-sidebar*

	The default view is a folder tree. Below two header lines («Changes
	(N)» and «Showing changes for: <base>..<head display name>»; the head
	display name is «working tree» on the normal path and the saved ref
	name when degraded to the read-only scratch) follows the path tree. dir
	rows end with «/» to distinguish them from files; their status = the
	aggregation of children (same symbol = as-is, mixed = «*»). Single-child
	dir chains render joined («a/b/c/»). File rows are «[✓?] <status>
	<comment-icon?> <icon?> <basename> +a -d»; +n green, -n red; files with
	comments get a comment icon (nf-cod-comment; a Nerd Font glyph) after the
	status (no parent path — the tree indent is the context). filetype icons
	show automatically only when nvim-web-devicons is installed (plain text
	without it).
	The review-done mark [✓] sits at the start of the row. Never set by
	open/movement — only the panel's x toggles it (saved in the session and
	restored after restarts).

	<CR>
	  file row = open the file in the head/base windows. focus and cursor
	  stay in the panel (opening never sets the review-done mark). dir row =
	  toggle fold (cursor stays on the dir row)

	o
	  same as <CR>, «open the entry» (the «open the real file in another
	  tab» that existed until 2026-09 was removed — the head window is the
	  real file itself)

	l		same as <CR>, «open the entry» (a tree-UI convention alias)

	<Tab>
	  next file (list order = the same handling as <CR>; focus stays in the
	  panel; no-op at the edges)

	<S-Tab>		previous file (ditto)
	[F		first file (same rule as above)
	]F		last file (same rule as above)
	R		refetch the diff (same as R in the review windows)

	i
	  toggle list view (full path 1 line) / tree view. filter, folds and
	  the selected row carry over across the toggle but are not saved to
	  the session file (reopening returns to the tree default)

	x
	  toggle the review-done mark [✓] (no-op on dir header rows; open and
	  movement never set it automatically)

	/
	  filter the list. input = case-insensitive substring match on paths
	  for the redraw. empty input clears, Esc keeps the current filter.
	  While filtering, <CR>/o/l/x/<Tab>/<S-Tab>/[F/]F also walk only inside
	  the matching set (winbar shows the match count and filter)

	q		close the session (same as q in the diff windows)
	<leader>c	open the comments list (same as the diff windows)
	<F1> / g?	keymap help float (same as the diff windows. g? is a fixed alias)

	Cursor movement in the panel alone never swaps the diff. Conversely
	open_file scrolls the panel cursor to the row (mutual highlight:
	selection + cursorline). Movement keys pressed from the panel
	(<Tab>/<S-Tab>/[F/]F) return focus to the panel too (from the review
	windows focus stays in the head window).

 comments list (cross-file)			*review-keymaps-commentlist*

	All comments of the session in one cross-file list
	(`review://comments/<session-id>`). The list opens full-width at the
	bottom of the review tab (default height 10 lines, configurable via
	`comment_list_height`) and its position never depends on which window
	you press from. 1 row = 1 comment formatted
	«<path>:<line>[-<end>]  [<id>]  <body line 1>» (anything beyond 60
	columns trails in …; outdated rows append « ⚠ outdated»). Order = the
	same tree display order as the file panel (folds / list view are not
	reflected) → line ascending within a file. The filter (/) IS applied and
	the winbar shows «<base>..<head display name> · N comments [· ⚠M]»
	(0 comments can still be opened).

	<CR>
	  jump to the comment on the cursor line. Opens the real file (or the
	  degraded-head scratch) and moves to the recorded line (clamped to the
	  last line when out of range; folds are opened). outdated comments
	  jump to the recorded line with INFO. Files shown as binary / deletion
	  notices and files not in the current diff do not move (WARN)

	d
	  delete the comment on the cursor line (list-only arming: press d
	  again on the same line to confirm. Cancel with <Esc> / 2s / a
	  confirmed edit)

	D
	  delete all comments at once (list-only arming: press again to
	  confirm. Same as :Review clear. Comments hidden by the filter are
	  deleted too. Cancel with <Esc> / 2s / a comment count change)

	e
	  edit the comment on the cursor line (same input float as the diff
	  window. Saving also refreshes the list)

	y
	  copy the prompt of the single comment on the cursor line to "0 (+the
	  clipboard). outdated rows are not copied (INFO)

	q		close the list (the session state is untouched)

 Sessions list (:Review list)			*review-keymaps-sessionlist* *review-list*

	<CR>		open the selected session (closed -> open)
	q		close the list (the session state is untouched)

	d
	  delete the selected session (the same confirm flow as :Review delete)

==============================================================================
SESSION state and recovery			*review-sessions*

Saved sessions have two states, open / closed (1 line each in the list):

 The contractual "close" operations are q / `:Review close` (same procedure):
 save comments + completion marks and set closed, close the review tab and
 clean up plugin-made worktrees (closed sessions cannot be restored by
 `:Review` and are only reopened from `:Review list`; opening flips back to
 open and the worktree is regenerated).

	Directly closing the review tab with `:tabclose` / `:tabonly` etc. is
	distinct from close: comments and the open state stay saved
	(status=open) and only extmarks and keymaps are cleaned up, plus the
	INFO «review tab closed (session saved; reopen with :Review)». The
	next `:Review` reopens it. The real-file buffer that was in the head
	window (unsaved edits included) and user windows / tabs are never
	discarded on either path.

	Neovim crash
	  The JSON stays in the data dir with status=open and the next start
	  sends the «you can resume…» notification (:Review restores it;
	  worktree leftovers are swept by the startup scan)

	Auto-apply on save
	  Saved diffs are automatically reflected in the review. Saving a
	  reviewed file (either :w in the head window or a user window; the
	  read-only scratch during degradation is excluded) refetches the diff
	  and reapplies the ±counts, comment positions (anchor correction /
	  outdated), threads and :Review prompt against the latest saved
	  state; the window diff recomputes on save. Unsaved buffer edits show
	  in the view only and never reach counts or prompts. A failed refetch
	  WARNs and keeps the previous view and comments.

Comments whose recorded position is no longer resolvable after diff drift
(outdated) show as line-end `comment-icon N` + the thread under the line when
they resolve inside the head buffer (outdated id prefixes in warning color,
bodies in plain color); unresolved ones aggregate in a box above line 1 of the
head buffer headed «N outdated (excluded from prompt)», and comments of files
without a window (deleted/binary notices) show as `⚠N` at the end of the file
panel winbar (:h review-display). They are excluded from the default
`:Review prompt` output. Bodies are never lost — they remain in the pre-close
JSON, and walking refs back can make them active again.

DISPLAY characteristics				*review-display*

The three review windows			*review-display-diff*

	Reviews open in a dedicated tabpage as file panel (left; default width
	35) │ base │ head. The tab is tcd'ed to the repo / worktree (for LSP
	spawn cwd and relative-path resolution).

	head window
	  the new side of the diff = the real file itself (:edit). Editable,
	  filetype / LSP work. Comparison with base is Neovim's standard window
	  diff (DiffAdd / DiffChange / DiffDelete / DiffText); folds, `[c` /
	  `]c` hunk movement and scrollbind stay standard (unmapped). Added and
	  deleted files exit the window diff and open in plain colors; the type
	  is told by the winbar marks (` · new file` / ` · deleted`).

	base window
	  the read-only scratch of `git show <base>:<path>`. Added files get a
	  0-line scratch; deleted / binary files are replaced by a notice
	  scratch; such pairs leave the window diff in both windows (diffoff).

	comments-list window
	  the cross-file list opened by `<leader>c` / `:Review comments`.
	  Full-width at the bottom of the tab (10 lines by default) and never
	  joins the window diff (details: |review-keymaps-commentlist|).

	head/base degradation (scratch degradation)
	  both windows become read-only git show (INFO notified).

	Comments live as extmarks in the head buffer (an underline across the
	range + line-end `comment-icon N` on the last row; a mixed old/new
	group keeps the count, outdated id prefixes go warning color). Bodies
	render as a thread in a ruled box (`┌─┐ │ └─┘`) under the last row of
	the range (GitHub-style. The box spans the head window's text width so
	its right edge always aligns to the window's, bodies wrap inside, 10
	lines then truncate; full text: the `i` window, filetype markdown).
	Threads are visible in every window that shows the buffer (Neovim has
	no window-local virt_lines; measured). Buffer lines are not consumed,
	so the line-number mapping stays intact (narrower windows clip the
	right edge). Unresolvable outdated comments aggregate in a box headed
	«N outdated (excluded from prompt)» above line 1 of that head buffer;
	comments of files with no window (notice windows / files gone from the
	diff) go to the trailing `⚠N` of the file panel winbar.

==============================================================================
COMMENT INPUT					*review-comment-input*

Confirming and closing the comment input float (filetype=markdown) opened by
c/e:

	<CR>		confirm in Normal. <CR> while inserting is a newline

	q
	  close in Normal. An empty body cancels. With a body the window stays
	  open and only a second q (within 2s) discards the input and closes

	<C-y>		confirm while inserting (alias)
	<Esc>		return to Normal only (the window stays)

The window title shows the target `path:line` and the confirm/close
operations. The same list lives in the <F1> help float.
