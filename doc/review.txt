==============================================================================
INTRODUCTION					*review* *review-nvim*

review.nvim は GitHub の Files changed のようにブランチ間 (git ref 間) 差分を
Neovim 内でレビューし、コメントを蓄積して AI エージェント向けプロンプトとして
出力するプラグイン。永続化したコメントは Neovim 再起動後 `:Review` 1 操作で
復元できる。

==============================================================================
USAGE						*review-usage*

すべての操作は単一コマンドとそのサブコマンドで行う:

	:Review					続きのセッションを復元。open
					状態のみが対象で、複数あれば選択 UI。
					closed は |review-list| から再開する
	:Review start {base} [{head}]		ブランチレビュー開始。レビュー
					対象は現在のチェックアウトの作業ツリー
					(未コミット変更を含む)。{base} / {head}
					は cmdline で <Tab> により branches ->
					tags 順に補完される (取得は同期・短時間
					cache)。head 省略時は現在のブランチ名
					(rev-parse --abbrev-ref HEAD。detach
					では "HEAD") を自動採用・保存し、入力
					UI は出さない。head を明示して現在の
					HEAD と違うコミットを指す場合、head が
					ローカルブランチで作業ツリーが clean
					なら git switch するか [y/N] で確認する
					(承諾 = switch してレビュー、拒否・
					dirty・非ローカルブランチ・switch 失敗
					= git show 内容の読み取り専用レビューに
					縮退し INFO 通知)。branch レビューでは
					worktree を作らない。head 窓で :w すると
					差分が自動で再取得されレビューに反映
					される (|review-sessions| の
					「保存時自動反映」)。同一 refs 組の
					保存済みセッションがある場合は「継承
					するか」の [y/N] 確認が出る (y で
					comments / viewed を引き継ぎ、n で
					何もしない)
	:Review pr {number|url}			PR レビュー開始 (gh 連携)。
					{number} は <Tab> で open PR の番号が
					補完できる (gh を同期実行)。
					head を git worktree に展開し、レビュー
					窓 (tcd 済み) の head 側が worktree 内の
					実ファイルになる (worktree 作成は pr
					モードのみ。掃除は |review-sessions|)
	:Review list				保存済みセッション一覧 |review-list|
	:Review close				現セッションを保存して閉じる |review-sessions|
	:Review delete {id}			保存済みセッションを削除
					<id> は <Tab> で保存済み id が補完できる
	:Review prompt [file]			プロンプトをクリップボードへ

確認プロンプト ([y/N] 等) は y か n を押して <Enter> で応答する。応答まで
他の打鍵はそのプロンプトに入力として吸収される (cmdline に混ざらない)。

==============================================================================
API						*review-api*

Lua から呼ぶ公開 API (~require("review")~)。同じ操作のコマンドライン相当は
|review-usage| を見る。戻り値は結果型 `{ok, data, error, code}` で、同期的に
判定できる失敗 (引数不正、active 不在 `E_NOT_ACTIVE`、config 不正) を表す。
git/gh を伴う実行の成否は非同期に UI 開閉か vim.notify で返る。

	setup(opts)			config 合成と初期化 (省略可、既定値で
					動作)。設定項目は |review-setup|
	start({ base=[, head=] })	ブランチレビュー開始。head 省略時は
					現在のブランチ名を自動採用・保存する
					(入力 UI なし)。振る舞いは
					|review-usage| と同じ
	start_pr({ number= })		PR レビュー開始 (gh 連携、|review-usage|)
	resume({ id= })			保存済みセッションを id で復元
	close()				現セッションの save + 窓を閉じる +
					worktree 掃除
	delete({ id= })			保存済みセッションを削除 (worktree
					掃除含む。active な id も可)
	prompt_all(opts)		全コメントのプロンプトを整形し
					クリップボード/"0 へ。opts.copy = false
					でコピーせずに text を返す (テストフック)
	prompt_for_file(path, opts)	そのファイルのコメントのみ同上

==============================================================================
SETUP						*review-setup*

>
	require("review").setup({
		git_bin = "git",           -- git 実行ファイル
		gh_bin = "gh",             -- gh 実行ファイル (PR 用)
		diff_context = nil,        -- diff context 行数 (nil = git 既定 3)
		auto_notify_resume = true, -- 起動時に open セッションを通知
		panel_width = 35,          -- file panel (左窓) の幅
		keymaps = {},              -- buffer-local キーマップ override
		highlight = {},            -- グループ別 highlight override
		winbar = true,           -- review 窓に winbar 情報 (既定 on)
		number = false,            -- review 窓の行番号 (既定 off、global は不変)
	})
<

setup は省略可能。呼ばなくても既定値のキーが貼り付き、起動時の継続通知と
worktree 残骸スキャンは走る (plugin read 時点で登録されるため)。設定を
後から渡す場合も |review-sessions| の起動通知は設定値を実行時に読む。

KEYMAPS						*review-keymaps*

すべてのキーマップは buffer-local。押した箇所 (バッファ種別) が違うと効く
キーも違うので、以下のセクションで引くこと。

既定値の全体と override の書式:

	keymaps = {
		diff = {                      -- レビュー窓 (head / base)
			add_comment    = 'c',     -- |review-comment-input|
			edit_comment   = 'e',
			delete_comment = 'd',
			yank_prompt    = 'y',
			open_file      = 'o',
			close          = 'q',
			help           = '<F1>',
			next_file      = ']d',
			prev_file      = '[d',
			focus_sidebar  = 'S',
			focus_panel    = '<leader>e',
			toggle_panel   = '<leader>b',
			view_comments  = 'i',
		},
		sidebar = {                   -- file panel (変更ファイル一覧)
			open_diff      = '<CR>',
			open_file      = 'o',
			toggle_viewed  = 'x',
			filter         = '/',    -- |review-keymaps-sidebar|
			close          = 'q',
		},
		sessionlist = {               -- :Review list の一覧
			open           = '<CR>',
			close          = 'q',
			delete         = 'd',
		},
	}

>
	require("review").setup({
		keymaps = { diff = { add_comment = 'gc' } },
	})
<

レビュー窓 (head / base)			*review-keymaps-diff*

	レビューは専有 tabpage の 3 窓 (file panel │ base │ head) で開く。head 窓は
	実ファイル (`:edit`・編集可)、base 窓は `git show` の scratch。2 窓は Neovim
	標準の窓 diff なので hunk 移動の `[c` / `]c` や fold が標準のまま効く。以下の
	キーは head / base 窓に buffer-local で貼り、押した時点の窓 role gate を通る
	ものだけが発火する。gate を通らない窓 (ユーザーが自分の窓で開いた同じ実
	ファイルなど) では 1 キーストロークが built-in 動作に戻る (レビュー操作は
	誤発火しない)。

	c		コメント作成 (head 窓のみ)。visual-line で範囲指定。base 窓・
			削除/binary 告知窓では «この窓にはコメントを付けられません»
	e		カーソル行のコメントを編集 (入力窓は
			|review-comment-input|)。その行に複数ある場合
			は番号選択のプロンプトになる (既定の
			vim.ui.select = `Type number and <Enter>`)
	d		カーソル行のコメントを削除。誤爆防止の二重押し:
			1 回目は armed + WARN だけを発し、同じ行で 2 秒
			以内に続けて d で削除が確定する (vim 筋の dd で
			複数件が消えないため)。arming は他行移動・e での
			編集確定・2 秒経過で解除
	y		カーソル行のコメントのプロンプトを yank
	o		そのファイルの実ファイルをレビュー tab の外 (前行儀の
			tab) で開く。削除ファイルは «開けません» の WARN
	q		セッションを閉じる (コメント 0 件は無確認)
	<F1>		キーバインドの help float
	]d		次のファイルを開く (head/base を張り替え。パス昇順の並び。
			端では無動作。viewed 更新と save は一覧の <CR> と同じ)
	[d		前のファイルを開く (上記と同じ規則)
	S		file panel (変更ファイル一覧) へ移動 (窓が閉じて
			いれば左に再建してから移動)
	<leader>e	file panel へ移動 (S と同一処理)
	<leader>b	file panel の表示トグル (閉じても tab とレビュー窓は残る)
	i		カーソル行のコメント全文を read-only 窓で閲覧
			(編集は e)。q / <Esc> で閉じる

 file panel (変更ファイル一覧)			*review-keymaps-sidebar*

	<CR>		そのファイルを head/base 窓に開き、focus を head 窓へ
			移動 (viewed 自動 true)
	o		そのファイルの実ファイルを開く (diff の o と
			同じ規則)
	x		viewed 切替
	/		一覧を絞り込む。入力 = paths の大文字小文字無視の
			部分一致で再描画。空入力で解除、Esc で現状維持。
			絞り込み中は <CR>/o/x/]d/[d も一致集合内だけを
			辿る (winbar に一致数と filter が出る)
	q		セッションを閉じる (diff の q と同じ)

セッション一覧 (:Review list)			*review-keymaps-sessionlist* *review-list*

	<CR>		選択セッションを開く (closed -> open)
	q		一覧を閉じる (セッション状態は変えない)
	d		選択セッションを削除 (:Review delete と同じ
			確認フロー)

SESSION 状態と復旧				*review-sessions*

保存済みセッションには open / closed の 2 状態がある (list で 1 行表示):

 契約化された「閉じる」操作は q / `:Review close` の 2 つ (同じ手順): comments +
 viewed を保存して closed にし、レビュー tab を閉じ、plugin が作った worktree を
 掃除する (closed は `:Review` では復元できず、`:Review list` からのみ再開できる。
 開くと自動的に open に戻り worktree は再生成される)。

	ユーザーがレビュー tab を `:tabclose` / `:tabonly` 等で直接閉じるのは close
	と区別される: コメントと open 状態は保存されたまま (status=open)、extmark と
	キーマップだけ掃除し、INFO «レビュー tab を閉じました (セッションは保存済み・
	`:Review` で開き直し可)» を出す。次回 `:Review` で開き直せる。head 窓に
	なっていた実ファイルバッファ (未保存編集を含む) とユーザーの窓・tab は
	どちらの経路でも消さない。

	Neovim 異常終了	 open のまま JSON が data dir に残り、次回起動時に
			「続けられます」通知 (:Review で復元 / worktree
			残骸は起動 scan が掃除)

	保存時自動反映	 保存した差分は自動でレビューに反映される。レビュー
			対象ファイルの保存 (head 窓でもユーザー窓の :w でも
			可。縮退中の読み取り専用 scratch は対象外) で差分を
			再取得し、±カウント・コメント位置 (anchor 補正 /
			outdated)・スレッド・:Review prompt が直近保存基準で
			再適用、窓 diff は保存時に再計算される。未保存の
			バッファ編集は表示にだけ映り、カウントと prompt に
			は入らない。再取得の失敗は WARN 通知で前の表示と
			コメントを保持する

outdated 認定 (差分の揺れで対象行を特定できないコメント) は head バッファで
 解ける位置にあえば行末 `(💬 N (⚠M))` と gray スレッド、head 窓に解けない分は
 head バッファ 1 行目の行上に «⚠ N outdated (prompt 除外中)» として集約、窓の
 さえないファイル (削除/binary 告知) の分は file panel winbar 末尾の `⚠N` で示す
 (:h review-display)。`:Review prompt` の既定出力からは除外される。本文は失わず
 closed 前の JSON に残るため、refs を戻せば再度 active として扱える場合がある。

表示の特性					*review-display*

レビューの 3 窓				*review-display-diff*

	レビューは専有 tabpage に file panel (左・既定幅 35)│base│head の横 3 窓で
	開く。tab は repo / worktree へ tcd される (LSP server の spawn cwd と
	相対パス解決用)。

	head 窓		差分の new 側 = 実ファイルそのもの (:edit)。編集可・
		filetype / LSP が効く。base との比較は Neovim 標準の窓 diff
		(DiffAdd / DiffChange / DiffDelete / DiffText) で、fold・`[c` /
		`]c` hunk 移動・scrollbind は標準のまま (マップしていない)。
	base 窓		`git show <base>:<path>` の読み取り専用 scratch。
		追加ファイルは 0 行 scratch、削除 / binary ファイルは告知
		scratch に置き換わり窓 diff から退避する (diffoff)。
	head/base の縮退 (scratch 縮退) は両窓 git show の読み取り専用になる
		(INFO 通知済み)。

	コメントは head 実バッファの extmark (対象行の下線 + 行末 `💬 N`、
	outdated 混在は `💬 N (⚠M)`、本文は**行下スレッド** virt_lines に GitHub 風、
	10 行で打ち切れ全文は `i` 窓)。スレッドはそのバッファを見る全窓に
	見える (窓単位で抑える API が Neovim に無い実測。バッファ行を占有しない
	ので行番号写像は不変)。位置を解けない outdated は その head バッファ
	1 行目の行上に «⚠ N outdated (prompt 除外中)» + 本文一覧として集約、
	窓のさえないファイル (告知窓 / 差分から消えたファイル) の分は file panel
	の winbar 末尾 `⚠N` に出す。

COMMENT INPUT					*review-comment-input*

c/e で開くコメント入力 (float) の確定と閉じる操作:

	<CR>		Normal で確定。insert 中はただの改行
	q		Normal で閉じる。本文がなければキャンセル。
			本文があるときは閉じず、続けて (2 秒以内に) q を
			押したときだけ入力を破棄して閉じる
	<C-y>		insert 中の確定 (エイリアス)
	<Esc>		Normal へ戻るだけで窓は閉じない

窓の title には対象の `path:line` と確定/閉じるの操作を表示する。<F1> の
help float にも同じ一覧がある。
