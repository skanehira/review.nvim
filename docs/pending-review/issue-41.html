finish_close の保存を persist() 経由に変えたことで保存対象が捕捉済み current.session から実行時 active.session になり、TabClosed との非同期交互実行で close/delete フローが error 中断しうる退行

evidence: 旧実装 (base 58ba4ea) の finish_close は store.save(current.session) で捕捉済み current を保存し、active が先に nil 化しても閉じ処理を完遂できた。新実装は persist() → store.save(active.session) で、on_review_tab_closed (finish_close を通らない唯一の active=nil 経路) が close_with_worktree の非同期窓 (git_worktree.status spawn / dirty 時 force 確認 confirm / worktree remove) の間に発火すると persist() が nil index で error を投げ、以降の detach / cb / worktree remove / delete の finalize がすべて中止される (delete 経路では JSON 残置 + 孤児 worktree)。persist() の呼び出し元 5 箇所のうち他 4 箇所 (begin_session / commit_comment_change / toggle_viewed_current / apply_refresh) は active 存在下の同期文脈で呼ばれるため非同期窓を跨いで active が nil 化し得るのは finish_close のみ

fix_hint: persist を persist(sess) 形に引数化 (既定 active.session) し、finish_close は current.session を渡す。「全 save 経路の唯一の出口」という設計の意図を保ったまま捕捉済みオブジェクトを保存できる
